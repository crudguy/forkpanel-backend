### P0-1 登录限速器的 HashMap 无界增长（未授权可触发的内存 DoS） ✅ 已修复

| 项 | 内容 |
|---|---|
| **位置** | `crates/panel-api/src/auth.rs:443-492`（`LoginGuard`） |
| **证据** | `attempts: Mutex<HashMap<String, Vec<Instant>>>`（:444）；`check()` 内 `m.entry(key.to_string()).or_default()`（:462）——**只读也会插入新 key**；`record_failure()`（:484）push；`reset()`（:489）仅在登录**成功**时移除 key |
| **分析** | ① `check()` 用 `entry().or_default()`，导致**任何一次登录尝试**（哪怕是随机编造的用户名）都会在 map 里留下一个 key；② 没有任何按时间/容量淘汰 key 的机制，`reset()` 只在成功登录时调用，失败路径的 key **永久留存**。攻击者用脚本刷不同用户名即可让 map 无限增长（每条约 100+ 字节，1M 条约 100MB+）。面板以 root 运行，OOM 会被 systemd/内核杀进程 → 面板整体不可用。 |
| **建议** | 三改动一起做（都很小）：<br>1. `check()` 改为**只读**：先 `m.get(key)`，没有就返回 `None`，不再 `entry().or_default()`（插入只保留在 `record_failure` 里）；<br>2. `record_failure()` 里加**容量上限**（如 10_000 条，超出时淘汰最旧 key，或直接拒绝新 key 的插入）；<br>3. 加一个惰性淘汰：`check()` 命中时顺带 `retain` 掉窗口外记录后若 `v.is_empty()` 则 `remove(key)`，让正常流量也能自愈。 |
| **预期收益** | 消除唯一一条「未授权请求可导致的 unbounded 内存增长」路径；顺带让正常用户的误输入 key 自动回收。 |
| **验证方式** | 加单测：`check` 一个从未出现的 key 后 `attempts.len() == 0`；连续 1 万次不同 key 的 `record_failure` 后 map 长度 ≤ 上限。 |

### P1-1 备份任务的同步 DB 拷贝跑在 async worker 上 ✅ 已修复

| 项 | 内容 |
|---|---|
| **位置** | `crates/panel-api/src/routes/backups.rs:568`（`BackupTask::execute`，:557 起为 `async fn`）→ `crates/panel-db/src/lib.rs:348`（`pub fn backup_file`，**同步**） |
| **证据** | `execute` 内直接 `panel_db::backup_file(&self.db_path, &dest)?`，无 `spawn_blocking` 包裹 |
| **分析** | `backup_file` 是 `Connection::open` + `VACUUM INTO` 的同步阻塞调用，却在 `async fn` 里被直接 await 前调用。panel-task 用 `tokio::spawn` 跑任务体（`crates/panel-task/src/lib.rs:348`），所以 DB 备份期间会**占住一个 tokio worker 线程**。库文件几十 MB 时是几百 ms（可接受），数百 MB 时是数秒——期间该 worker 完全无法服务其他请求。对照组：同文件的 `tar_gz` 走 `panel_os::cmd::run`（异步子进程，`backup.rs:11`）、`encrypt_file` 明确用了 `spawn_blocking`（`backup.rs:135`）——**说明这是漏改，不是设计**。 |
| **建议** | 把 `backup_file` 调用包进 `tokio::task::spawn_blocking`（入参 `PathBuf` clone 后 move 进闭包），与 `encrypt_file` 的处理保持一致。约 5 行改动。 |
| **预期收益** | 大库备份不再抢占 async worker；备份期间面板响应能力不受影响。 |

**修复记录**（commit `b5ee2fc`）：`backup_file` 调用包进 `tokio::task::spawn_blocking`（`PathBuf` clone 后 move，`JoinError` 映射 `PanelError::Internal`）。新增回归测试 `routes::backups::exec_tests::panel_backup_produces_a_readable_db`——跑通 `BackupJob::run` 全路径、断言产物 `.db` 可独立打开且 schema 齐全（**备份执行路径此前零自动覆盖**）。负向对照：把闭包里 `db`/`out` 对调 → 测试真红（`vacuum into: output file already exists`）。
